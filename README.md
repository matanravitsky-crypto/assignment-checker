# בודק העבודות

מערכת לבדיקה אוטומטית של תרגילי בית במתמטיקה בדידה ובאלגברה לינארית.

יש לה שלושה שלבים:
1. **משיכה:** ההגשות של המטלה מורדות ממודל, ממוספרות בלי שמות, ונשמרות בתיקיית OneDrive של הקורס.
2. **בדיקה:** כל עבודה נשלחת ל-Claude עם המחוון, הדגשים והפתרון הרשמי. Claude מסמן טעויות, נותן ניקוד לכל שאלה וכותב משוב. *(עוד לא מחובר)*
3. **החזרה:** הציון, המשוב וה-PDF המסומן מוכנים להעלאה חזרה למודל, ומישהו מהצוות מעלה ומאשר.

## הפעלה (הגרסה המחוברת)

פעם אחת במחשב:
1. **מסנכרנים את תיקיית הקורס:** בדפדפן, בתוך התיקייה `YallaLinearit`, לוחצים **Sync** ומתחברים עם חשבון האוניברסיטה. התיקייה מופיעה במחשב, למשל `C:\Users\<שם>\BGU\נדב מאיר - YallaLinearit`.
2. **מתקינים Python** 3.10 ומעלה, מ-https://www.python.org/downloads/ (אם עוד לא מותקן).

בכל פעם: לוחצים פעמיים על **`start.bat`**. האתר נפתח מחובר לתיקייה. בהפעלה הראשונה ההתקנה לוקחת כדקה.

## איך התיקייה מאורגנת

המערכת עובדת רק בתוך `YallaLinearit/Exercise Checking System`, במבנה שאורי הגדיר. בשאר התיקייה של המרצה היא לא נוגעת.

```
Exercise Checking System/
  README.txt                          הכללים של הצוות
  Linear Algebra/                     תיקייה לכל קורס
    README.txt                        רשימת המטלות (המערכת מעדכנת את מספר ההגשות)
    Assignment 0 - .../               תיקייה לכל מטלה
      Assignment details.json         מזהה במודל, מזהה קורס, מועד הגשה, שאלות, שם בעברית
      Key - number to student.csv     טבלת המפתח: מספר ↔ סטודנט. השמות נמצאים רק כאן
      1 - Submissions to grade/       0001.pdf, 0002.pdf... ממוספרות, בלי שמות
      2 - Graded with comments/       אותו מספר, עם ההערות (שלב הבדיקה)
      3 - Ready to upload to Moodle/  מה שמוכן להעלאה (שלב ההחזרה)
      Grades.csv                      number,grade,feedback (מה שהבדיקה מחזירה)
      Moodle download <תאריך>.zip     ה-ZIP בדיוק כפי שמודל נתן (כל הורדה נשמרת)
```

## איך מכניסים הגשות ומחזירים

לפי הכללים של הצוות (ב-`CLAUDE.md`), רק אחד מוריד ממודל ומעלה למודל. היום זה אורי. כך יש טבלת מפתח אחת לכל מטלה. למודל אין API, ולכן ההורדה וההעלאה נעשות בדפדפן.

**משיכה:**
1. במודל, בדף ההגשות של המטלה: פעולות ← "הורדת כל ההגשות". ה-ZIP נשמר ב-Downloads.
2. באתר המחובר לוחצים "משוך הגשות". אפשר גם בשורת הפקודה: `python -m moodle ingest <מזהה מטלה>`.
3. הקוד של אורי (`moodle/ingest.py`):
   - שומר את ה-ZIP בתיקיית המטלה.
   - מחלץ אותו עם 7-Zip למחשב בלבד, כי שמות הקבצים של הסטודנטים שוברים את הסנכרון של OneDrive.
   - ממספר כל הגשה ל-`0001.pdf`…, ומעדכן את טבלת המפתח.

   סטודנט שכבר יש לו מספר שומר עליו.

**בדיקה** *(עוד לא מחוברת)*: הבדיקה קוראת רק את `1 - Submissions to grade`, וכותבת שני דברים:
- `Grades.csv` עם העמודות `number,grade,feedback`.
- `2 - Graded with comments/<מספר>.pdf`: העבודה עם ההערות.

**החזרה:**
1. במודל: פעולות ← "הורדת גיליון ציונים". זה דורש להפעיל במטלה את Offline grading worksheet.
2. באתר לוחצים "הכן החזרה". אפשר גם בשורת הפקודה: `python -m moodle upload <מזהה מטלה>`.
3. בתיקייה `3 - Ready to upload to Moodle` נוצרים גיליון הציונים, קובצי ה-ZIP של המשוב וקובץ `Upload steps.txt` עם ההוראות.
4. ההעלאה למודל נעשית ביד, ומישהו מהצוות מאשר אותה.

**פרטיות:** האתר מציג רק מספרי הגשות. השרת המקומי שולח לדפדפן רק קובצי PDF מתיקיות 1-2-3, ואת טבלת המפתח אי אפשר לפתוח דרכו. לא מעתיקים קבצים מהתיקייה ל-GitHub, כי הריפו ציבורי.

## הגדרות

הפרטים של כל מטלה (המזהה במודל, מועד ההגשה והשאלות) נמצאים ב-`Assignment details.json` שלה.

המשיכה דורשת **7-Zip**:

```bash
winget install 7zip.7zip
```

**`.env`** נמצא בתיקיית הריפו במחשב בלבד. הוא לא עולה ל-GitHub ולא ל-OneDrive, ויש בו את מפתח Claude לשלב הבדיקה:

```
ANTHROPIC_API_KEY=...
```

## מבנה הקוד

| קובץ | מה הוא עושה |
|---|---|
| `start.bat` | הפעלה בלחיצה כפולה |
| `moodle/` | הקוד של אורי: `ingest` (משיכה ומספור), `upload` (הכנת ההחזרה), `status`, `guide`. השמות של כל התיקיות מוגדרים ב-`moodle/paths.py` |
| `pipeline/config.py` | איפה נמצאת התיקייה `Exercise Checking System` במחשב |
| `pipeline/team.py` | קריאה של המבנה, לתצוגה באתר |
| `pipeline/service.py` | מחבר את הכפתורים לקוד של אורי, ומכין לאתר את המצב של כל מטלה |
| `pipeline/server.py` | השרת המקומי: מגיש את האתר ואת הכפתורים |
| `pipeline/demo.py` | קובצי PDF לדוגמה, לבדיקות |
| `docs/` | האתר: `app.js` (המסכים), `data.js` (נתוני ההדגמה), `api.js` (הדמיית השלבים בגרסת ההדגמה) |
| `tests/` | בדיקות אוטומטיות |

## פקודות שימושיות

```bash
python -m pipeline list
```
מציג את הקורסים, המטלות ומספר ההגשות.

```bash
python -m moodle status <מזהה מטלה>
```
מראה מה כבר נעשה במטלה.

```bash
python -m pytest
```
מריץ את כל הבדיקות: גם של האתר וגם של `moodle/`.

`CLAUDE.md` מסביר את התמונה המלאה, לכל מי שעובד על הפרויקט עם Claude.

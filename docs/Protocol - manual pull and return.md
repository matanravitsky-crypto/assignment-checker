# פרוטוקול: משיכה ידנית ממודל והחזרה ידנית למודל

נכתב 2026-11-16, אחרי הפגישה הטכנית של 15/11. מחליף את "Protocol - download and upload.md" (ההורדה הלילית עם Claude
בכרום, `--parts`, 30 MB, "Pull only on this computer": כל אלה כבר לא נכונים).

**העיקרון: Claude לא ניגש למודל.** אדם מהצוות מוריד ומעלה בדפדפן שלו. הקוד בודק, ממספר, מכין ורושם. כל דבר שעולה
למודל עולה ביד, אחרי "כן" של אדם, ובפעם הראשונה רק על מטלת ניסיון.

מה צריך במחשב: הריפו `assignment-checker` עם `.venv` (`start.bat` מתקין), 7-Zip, וגישה לתיקייה המשותפת (מסונכרנת, או
`ASSIGNMENT_DATA` לעותק מקומי). הפקודות רצות מתיקיית הריפו. `<מזהה>` = `id=` בכתובת המטלה במודל.

## חלק א: משיכה

### 1. להוריד ממודל (אדם)
בעמוד ההגשות של המטלה (`.../mod/assign/view.php?id=<מזהה>&action=grading`):
1. לוודא ש"הורדת הגשות המאורגנות לתיקיות לפי סטודנט" מסומן (ליד "פעולות"). בלי זה אין מזהה משתתף לקבצים והמשיכה מסרבת.
2. מטלה **עד כ-100 הגשות**: פעולות ← "הורדת כל ההגשות (השתמש ב 7ZIP לפתיחה)". קובץ אחד יורד ל-Downloads:
   `<קוד קורס>-<שם המטלה>-<מזהה>.zip`.
3. מטלה **גדולה** (מודל חותך ZIP של מאות MB באמצע וכרום שומר אותו כאילו נגמר): מורידים עמוד אחרי עמוד.
   - למטה בטבלה: "הצגה" ← 100 בעמוד. אפשר לסנן "הוגש" כדי לא להוריד ריקים.
   - בכל עמוד: תיבת הסימון של "בחר הכול" ← למטה "עם ההגשות שנבחרו..." ← "הורדת ההגשות שנבחרו" ← המשך.
   - כל עמוד יורד באותו שם, וכרום מוסיף `(1)`, `(2)`... לא משנים שמות ולא מחלצים כלום ביד.
   - עמוד שירד קטוע (הקוד יגיד "incomplete"): מורידים אותו שוב. אם שוב קטוע: "הצגה" 50, ומורידים את שני החצאים.
4. לא נוגעים ב-Downloads עד שהקוד לקח את הקבצים. רשימת חלקים ישנה של האתר (`<שם>-<מזהה>.json`) אם נשארה שם: למחוק קודם.

### 2. להכניס (הקוד)
```bash
python -m moodle list                      # איזו תיקיית נתונים המחשב רואה, ואיזו מטלה היא איזה מזהה
python -m moodle ingest <מזהה> --expected <כמה "הוגש" מודל מראה>
```
מטלה חדשה (עוד אין לה תיקייה): `python -m moodle ingest <מזהה> --course "Linear Algebra" --name "Assignment 2 - Linear systems"`.

מה קורה: הקוד מדפיס אילו ZIP-ים הוא לוקח (כל ZIP של המטלה ב-Downloads, גם העותקים), בודק כל אחד עם 7-Zip, מחלץ
את כולם לתיקייה אחת במחשב (`Moodle originals`, לא בשיתוף), וממספר: כל סטודנט שכבר בטבלת המפתח שומר על המספר שלו,
חדשים מקבלים את הבאים בתור, סטודנט שהופיע בשני עמודים נספר פעם אחת. הקבצים נכתבים ל-`1 - Submissions to grade/`,
קובץ שהגשה חדשה החליפה עובר ל-`Earlier versions/`, שום דבר לא נמחק. ה-ZIP-ים עוברים לגיבוי במחשב שמשך.

### 3. לבדוק
הקוד מדפיס בסוף את `Pull report.txt` (נשאר בתיקיית המטלה, ליד `Pull check.json` במספרים): כמה הגיעו, כמה היו צפויים,
ומה נבדק. `python -m moodle status <מזהה>` ו-`python -m moodle list` מראים את המצב בכל עת.
- מספר ההגשות שווה למספר "הוגש" במודל? אם חסר: עמוד שלא ירד. מורידים אותו ומריצים `ingest` שוב (מוסיף רק את החדשים).
- אין שמות ש-OneDrive יסרב להם ("All file names are safe to sync").
- באתר: המטלה מראה את המשיכה (מ-`Pull log.csv`) ואת מספר העבודות לבדיקה. אם התיקייה מקומית: להעלות לוואן דרייב
  (רק את תיקיית הקורס, לא את `Moodle originals`).

## חלק ב: החזרה

### 1. לפני: מה מוכן
העבודות המסומנות ב-`2 - Graded with comments/NNNN.pdf` (1-2 MB כל אחת), ציון לכל מספר ב-`Grades by <שם>.csv` /
`Grades.csv`, ואישור של מתרגל בתור הבדיקה הידנית. כל סקיל בדיקה (גם של נדב) חייב לכתוב לשם: ההחזרה מכירה רק את
התיקייה הזו ואת הציונים לפי מספר.

### 2. להוריד את גיליון הציונים (אדם, אם רוצים להחזיר ציונים)
פעולות ← "הורדת גיליון ציונים". מופיע רק אם "גיליון ציונים לא מקוון" (Offline grading worksheet) דלוק בסוגי המשוב של
המטלה. רק המרצה מדליק; אנחנו לא נוגעים בהגדרות. הקובץ יורד ל-Downloads בשם שמסתיים במזהה המטלה. מורידים אותו
**ממש לפני** ההכנה: מודל מדלג על שורה ששונתה אצלו אחרי מועד ההורדה.

### 3. להכין (הקוד)
```bash
python -m moodle upload <מזהה>
```
ב-`3 - Ready to upload to Moodle/`:
- `Upload batch <id>/Graded - part 01.zip` ...: רק עבודות חדשות או ששונו מאז ההעלאה האחרונה שלהן. בכל ZIP תיקייה
  לסטודנט בשם המקורי ממודל ובה `feedback.pdf`. עד 100 עבודות בכל ZIP (ברירת המחדל מ-18.11.2026, גם בכפתור "הכן להחזרה"
  באתר; הגשה 0: 11-12 קבצים), כדי שהייבוא במודל לא ייתקע על קובץ גדול, ואף ZIP לא עובר 730 MB (הדף במודל אומר 750).
  `--per-zip N` למספר אחר (0 = רק לפי גודל), `--max-mb` לגודל אחר.
- `Grades for Moodle worksheet.csv`: הגיליון שהורד, ממולא לפי **מזהה המשתתף** של כל סטודנט (אף פעם לא לפי סדר
  השורות). בלי גיליון ב-Downloads: הקוד אומר שהציונים לא מולאו, וה-ZIP-ים מוכנים בכל זאת.
- `Upload steps.txt`: הצעדים, רשימת ה-ZIP-ים עם גודל ומספר קבצים, מה לבדוק.
- **האימות** (`Return check.txt` בתיקיית המטלה): אחרי האריזה הקוד פותח כל ZIP שנוצר ובודק מחדש מהדיסק, לכל קובץ: התיקייה
  היא בדיוק זו שטבלת המפתח נותנת למספר, הקובץ זהה בייט לבייט לעבודה הבדוקה של אותו מספר, הציון בגיליון הוא ציון
  אותו מספר, אף אחד לא פעמיים ואף אחד לא חסר, וכל ZIP מתחת לגבול. כישלון אחד מוחק את האצווה: שום דבר לא "מוכן".
הפקודה מדפיסה: כמה סטודנטים, כמה קבצים, כמה ZIP-ים, שהאימות עבר, מי נשאר בחוץ (גדול מדי, הוגש מחדש אחרי הבדיקה, בלי אישור).
היא מסרבת בזמן משיכה או העלאה, כשיש עותק כפול של OneDrive של המפתח/היומן/האצווה, וכשטבלת המפתח לא עקבית.

### 4. להעלות את העבודות (אדם)
`Upload steps.txt` מכיל קישור ישיר לדף ההעלאה של המטלה, וליד ה-ZIP-ים יש קיצור דרך "Open the upload page in Moodle"
(לחיצה כפולה פותחת את הדף בדפדפן, שכבר מחובר למודל). דרך התפריט: פעולות ← "העלאת מספר קובצי משוב כקובץ 7Zip אחד".
לכל ZIP, לפי הסדר:
1. גוררים את ה-ZIP מ-`Upload batch <id>/` לתוך תיבת הקובץ שבדף ← "יבוא קבצי משוב". **הייבוא מיידי. אין מסך אישור.**
2. מודל חוזר לעמוד ההגשות עם "N קבצים יובאו". N חייב להיות שווה למספר הקבצים של ה-ZIP ב-`Upload steps.txt`.
3. תואם: `python -m moodle record <מזהה> "Graded - part 01.zip"`. זה רושם ב-`Upload log.csv` (מספרים בלבד), האתר
   מראה "הוחזר", וההכנה הבאה לא אורזת אותם שוב.
4. לא תואם: עוצרים. לא ממשיכים ל-ZIP הבא ולא מריצים `record`. בודקים במודל מה יובא (העלאה חוזרת של אותו ZIP רק
   מחליפה את אותם קבצים, לא מכפילה).

### 5. להעלות את הציונים (אדם)
אחרי שכל ה-ZIP-ים עלו: דף העלאת הציונים (הקישור השני ב-`Upload steps.txt`, או הקיצור "Open the grades upload page in
Moodle" בתיקיית ההעלאה; בתפריט: פעולות ← "העלאת גיליון ציונים") ← גוררים לשם את `Grades for Moodle worksheet.csv` ←
מודל מציג רשימה של השינויים ← מאשרים רק אם מספר הציונים ברשימה הוא המספר שההכנה הדפיסה (או פחות, אם חלק כבר היו
במודל כך). אחרת מבטלים.

**מה זה "גיליון ציונים לא מקוון" ולמה הוא קריטי.** סוג משוב בהגדרות המטלה במודל. כשהוא דלוק, "פעולות" מקבל את "הורדת
גיליון ציונים" ו"העלאת גיליון ציונים", והציונים של כל הסטודנטים נכנסים בפעולה אחת מקובץ CSV. כשהוא כבוי אין דרך
להכניס ציונים חוץ מהקלדה לכל סטודנט בנפרד. ב-16/11/2026 הוא כבוי בכל המטלות (אין "הורדת גיליון ציונים" בתפריט).
קובצי המשוב עוברים בערוץ אחר ("קובצי משוב") ועובדים בלי קשר.
אחר כך מוחקים מ-Downloads את הגיליון שהורד (יש בו שמות ומיילים). העותק בתיקיית המטלה נשמר בלי שמות.

## אם משהו לא הסתדר
| מה קרה | מה עושים |
|---|---|
| `No ZIP ending in -<מזהה>.zip` | ה-ZIP לא ב-Downloads, או שהשם שלו לא נגמר במזהה (הורדה ממטלה אחרת?) |
| "incomplete or broken" | ה-ZIP נחתך. הקובץ קיבל "(incomplete)" בשם. מורידים את אותו עמוד שוב ומריצים שוב |
| "not in a folder per student" | "הורדת הגשות בתיקיות" היה כבוי. מסמנים ומורידים שוב |
| "New assignment ...: give --course and --name" | מטלה בלי תיקייה: מוסיפים את שני השמות באנגלית |
| "key ... broken" / "conflict copies" | טבלת המפתח לא תקינה או שיש עותק כפול של OneDrive. לא מושכים עד שאדם מתקן |
| `upload`: "מושך/מעלה את המטלה הזו עכשיו" | נעילה של מישהו אחר. מחכים. נעילה בת 30 דקות ויותר נחשבת תקועה |
| `record`: "לא ברשימת האצווה" / "השתנה" | ה-ZIP לא מההכנה האחרונה. מכינים שוב ומעלים את ה-ZIP החדש |
| "N קבצים יובאו" קטן מהצפוי | מודל דילג על קבצים (למשל זהים להגשה). בודקים את הסטודנטים החסרים בעמוד ההגשות לפני שממשיכים |
| אין "הורדת גיליון ציונים" בתפריט | "גיליון ציונים לא מקוון" כבוי. מבקשים מהמרצה. העבודות עולות בלי זה; הציונים לא |

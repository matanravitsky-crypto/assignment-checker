# activity_log/: היומן

מי עשה מה ומתי, בתיקייה המשותפת. מודול נפרד, כדי שכל פעולה במערכת תוכל לכתוב אליו (היום: עריכת ציון).

```python
from activity_log import record, read

record(assignment_dir, "grade_edit", by="dana (PC)", number="0001", reason="...")
read(assignment_dir)                               # הכול, מהישן לחדש
read(assignment_dir, "grade_edit", number="0001")  # רק עריכות הציון של עבודה 0001
```

## איפה הוא נשמר

`<תיקיית המטלה>/Activity log/<מי>.jsonl`: שורת JSON לכל רשומה, וקובץ נפרד לכל מי שכותב.
כך שני מחשבים אף פעם לא כותבים לאותו קובץ, ו-OneDrive לא משאיר עותק סותר (אותו עיקרון כמו `Grades by <name>.csv`).
`read` מאחד את כל הקבצים (גם עותקים סותרים, בלי כפילויות) וממיין לפי הזמן.

שורות רק נוספות: אף שורה לא משתנה ולא נמחקת. שורה שנחתכה באמצע (המחשב כבה בזמן הכתיבה) מדולגת.

## מה יש בכל רשומה

| שדה | מה |
|---|---|
| `at` | מתי (שעון המחשב, עד השנייה) |
| `action` | איזו פעולה, למשל `grade_edit` |
| `by` | מי (`<user> (<PC>)`) |
| `pc` | באיזה מחשב |
| כל השאר | הפרטים של הפעולה |

רק מספרי עבודות, אף פעם לא שם, ת"ז או מייל של סטודנט.

## הפעולות שכותבות היום

- `grade_edit`: ציון נערך או אושר (`grading/grade_edit.py`). `number`, `from` ו-`to` (הציון לפני ואחרי), `points_from` ו-`points_to`
  (הניקוד לכל שאלה), `reason`, `kind` (`edit` עריכה של ציון קיים, `review` אישור מתור הבדיקה הידנית, `first` ציון ראשון
  לעבודה שהבדיקה שלה נכשלה), ו-`updated`: איפה הציון עודכן.
- `grade_edit_failed`: עריכה שלא הגיעה לכל המקומות: `updated` (איפה כן), `failed` (איפה נכשלה) ו-`error`.

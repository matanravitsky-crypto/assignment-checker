# website/: האתר

האתר עצמו: HTML, CSS ו-JavaScript, בלי בנייה ובלי ספריות חוץ מ-KaTeX (לנוסחאות). **כל מה שהוא מציג אמיתי**: הנתונים מגיעים מהמערכת שרצה במחשב ([`dashboard/`](../dashboard/), `start.bat`), שקוראת את תיקיית OneDrive של הקורס. בלי המערכת האתר לא מציג מספרים, רק הסבר איך מתחברים.

- **https://bodek-hacham.vercel.app** (מתפרסם לבד ב-Vercel מ-`main` בכל שינוי בתיקייה הזו, פרויקט `bodek-hacham`, תיקיית שורש `website`): פונה למערכת שבמחשב בכתובת `http://127.0.0.1:8765`. בפעם הראשונה כרום שואל אם לאפשר לאתר לגשת לאפליקציות ולשירותים במכשיר; עונים "אפשר". כל עוד start.bat לא פועל, האתר מנסה להתחבר שוב כל 5 שניות. כשהוא לא מחובר, יש בו כפתור בולט "פתח את המערכת" שמוביל ל-`http://localhost:8765`, שעובד בלי שום הרשאה של כרום, והסבר קצר להתקנה במחשב חדש (המלא ב-[README](../README.md)).
- **http://localhost:8765**: אותם קבצים, ישירות מהמערכת.
- **לוח המספרים הציבורי** (2026-11-03, "רק מספרים, לכולם"): מי שאין במחשב שלו מערכת רואה בכתובת הציבורית את "מצב העבודה": לכל קורס ומטלה כמה הגשות נמשכו, נבדקו, מחכות לבדיקה ידנית, אושרו והוחזרו, ומתי. הנתונים באים מ-`PUBLIC_STATUS_URL` (gist שמחשב אחד בצוות מעדכן, `dashboard/public_status.py`), מתרעננים כל דקה, ואם לא עודכנו יותר מ-3 שעות כתוב שהם אולי ישנים. בלי שמות, ציונים, הערות או קבצים. הכפתורים עדיין עובדים רק במחשב מחובר.

השרת מקבל בקשות רק מהמחשב עצמו ורק מהכתובת המדויקת של האתר ב-Vercel (לא מכתובות תצוגה מקדימה). ראו "אבטחה" ב-[`dashboard/README.md`](../dashboard/README.md).

**משיכה דרך ה-Claude של מי שלוחץ.** "משוך" (וגם "משוך הכול מחדש") עובר קודם באותה רשימת מוכנות כמו ההעלאה (`startPullFlow`): Claude Code מותקן, מחובר לחשבון של מי שבמחשב, והתוסף Claude in Chrome והמודל מחוברים בכרום. מה שחסר מתחבר שם (התחברות נפתחת לבד, התקנה רק אחרי "כן"), וכשהכול ✓ המשיכה מתחילה בלי לחיצה נוספת. בדיקה מ-30 הדקות האחרונות מספיקה, אז במחשב מחובר אין המתנה. הגשה ריקה (משיכה ראשונה עם קישור) הולכת ישר לשרת, ושם `require_moodle` בודק את כרום ומודל.

בלוח הבקרה, כל ריבוע קטן במסלול הוא עבודה: מעבר עם העכבר מגדיל אותו קצת ומראה את המספר שלה, ולחיצה כפולה מורידה אותה (במשיכה את ההגשה, בבדיקה ובהחזרה את העבודה הבדוקה). מתחת: סטטיסטיקה (ממוצע, חציון, סטיית תקן, עוברים, כמה מחכות לבדיקה ידנית וכמה אושרו) וטעויות נפוצות, לפי מה ש-Claude רשם ב-Grading notes.

**בדיקה ידנית** (`#/review`): התור של העבודות ש-Claude לא בטוח בהן או שהבדיקה שלהן נכשלה, עם המספר בתפריט. עבודה אחת בכל פעם: למעלה הבעיה במשפט, מצד אחד עמודי ההגשה כתמונות (`/api/page`) עם המלבנים של Claude במקומם, ומצד שני הציון. פתוחות רק השאלות שצריך לבדוק, ולכל שאלה הערות מוכנות עם הניקוד שלהן (לחיצה מורידה נקודות וכותבת את ההערה). "אשר ועבור לבאה" (או Ctrl+Enter) שומר דרך `POST /api/review`. אותו מסך פותח גם כל עבודה אחרת לתיקון ציון (`#/review?n=0023`).

**העתקות** (`#/copying`): זוגות של הגשות שנראות כמו אותה עבודה, בלי Claude ובלי טוקנים ([`copying/`](../copying/)). "בדוק העתקות" מריץ את ההשוואה ברקע (`POST /api/copying`). למעלה שלוש לשוניות: כל החשדות, שכבה 0 (אותו קובץ או אותו מקור) ושכבה 1 (אותו עמוד). לחיצה על זוג מראה את העמודים שנמצאו זהים זה לצד זה. בתפריט, מספר הזוגות עם חשד חזק. עמודים שחוזרים אצל הרבה הגשות מופיעים בנפרד, כדי שאדם יחליט אם זה דף שאלות או פתרון שעבר בקבוצה.

המספרים מתעדכנים רק ממה שנכתב בתיקייה: הגשות ב-"1 - Submissions to grade", ציונים ב-Grades.csv ועבודות מסומנות ב-"2 - Graded with comments", והעלאות שאומתו ב-Upload log.csv. גם יומן הפעילות נבנה מהתיקייה (`_activity` ב-`dashboard/actions.py`).

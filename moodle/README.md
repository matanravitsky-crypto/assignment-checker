# moodle/: הורדה ממודל והחזרה למודל

שלבים 1 ו-3. למודל אין API, ולכן ההורדה וההעלאה נעשות בדפדפן, והקוד כאן עושה את כל השאר.

| קובץ | מה הוא עושה |
|---|---|
| `paths.py` | השמות של כל התיקיות והקבצים בתיקייה המשותפת. כל קוד אחר לוקח אותם מכאן |
| `ingest.py` | שלב 1: לוקח את ה-ZIP מ-Downloads, מחלץ עם 7-Zip וממספר |
| `anonymize.py` | המספור (`0001.pdf`…) וטבלת המפתח. כל סטודנט שומר על המספר שלו בכל הורדה |
| `upload.py` | שלב 3: בונה את גיליון הציונים ואת קובצי ה-ZIP של המשוב, עם הוראות העלאה |
| `upload_log.py` | יומן ההעלאה (`Upload log.csv`) ורשימת האצווה (`Upload batch.json`, עם ה-sha256 של כל ZIP ושל כל קובץ): מה הועלה לכל מספר, בלי שמות. מספר נחשב מוחזר רק אם כל הקבצים שלו זהים להעלאה האחרונה. מוצא עותקים כפולים של OneDrive ולא מוחק אותם |
| `send.py` | הכנת אצווה להעלאה (`prepare_batch`): רק עבודות בדוקות חדשות או ששונו מאז ההעלאה האחרונה, ארוזות ב-ZIP-ים של עד 9 MB בתיקייה משלהן (`Upload batch <id>/`), עם `Upload batch.json`. מספר שהוגש מחדש אחרי הבדיקה, או שיש לו קובץ גדול מדי, נשאר בחוץ. מדווח על אלה ועל מספרים שלא אושרו ב-`Grades.csv` (בלי שמות). מסרבת בזמן משיכה או העלאה של המטלה, כשיש עותק כפול של טבלת המפתח, של היומן או של רשימת האצווה, וכשטבלת המפתח לא עקבית (מספר עם שני מזהי משתתף, מזהה משתתף עם שני מספרים, או תיקייה מקורית עם מזהה אחר). `run_batch` רץ על ה-ZIP-ים אחד אחרי השני: נועל את המטלה (`Upload in progress.txt`), ממשיך מהמקום שבו נעצר, נעצר לפי בקשה, בודק את ה-sha256 של כל ZIP לפני ההעלאה ולפני הרישום ביומן, ובודק שהמספר שמודל דיווח עליו שווה למספר הקבצים ב-ZIP. אם מודל ייבא והמספרים לא תואמים, הריצה נעצרת כ-`mismatch`, ואדם בודק במודל לפני שממשיכים. `SimulatedDriver` מדמה העלאה בלי לגעת במודל (להדגמות ולבדיקות) |
| `claude_driver.py` | ההעלאה למודל דרך Claude in Chrome: ריצה אחת נעולה של `claude -p --chrome` לכל ZIP, בתיקייה זמנית חדשה מחוץ ל-OneDrive שיש בה רק עותק של ה-ZIP (נבדק מול ה-sha256 ונמחק בסוף), ולא בתיקייה המשותפת: `--tools Read` (כלי הליבה כבויים חוץ מ-Read, בלי Bash, Edit ו-Write; Read מגיע רק לתיקייה הזמנית עם ה-ZIP היחיד, באישור המשתמש ב-2026-10-22; בדיקת החיבור רצה עם `--tools` ריק), `--allowedTools mcp__claude-in-chrome`, `--no-session-persistence`, `--json-schema`, `--max-budget-usd`, זמן מוגבל והמודל `claude-sonnet-5-5`, והפיכת התשובה שלה ל-`UploadResult`. לא זורק חריגות: כל כשל חוזר כתוצאה `error` עם הודעה בעברית. `find_claude()` מוצא את הפקודה `claude`, ו-`check` ו-`auth_status` בודקים שכרום, מודל ו-Claude Code מוכנים |
| `claude_upload.md` | תבנית ההוראות ל-Claude (`str.format`, בלי סוגריים מסולסלים חוץ מהשדות): כתובת אחת, שלבי ההעלאה, ובדיקה יבשה שנעצרת בביטול לפני הייבוא (הייבוא במודל מיידי, בלי מסך אישור: אין רשימת קובץ-לסטודנט לבדוק לפני הייבוא) |
| `lock.py` | עוזר משותף לקובץ נעילה בתיקיית המטלה, כדי ששני אנשים לא יריצו את אותו שלב על אותה מטלה יחד (תוקף 30 דקות מהעדכון האחרון). הקובץ אומר `<user> (<PC>) pid=<pid>`: גם נעילה של אותו אדם באותו מחשב חוסמת אם תהליך אחר שעדיין רץ מחזיק בה (למשל ה-CLI והאתר). המשיכה (`Pull in progress.txt`) וההעלאה (`Upload in progress.txt`) משתמשות בו |
| `status.py` | מה כבר נעשה במטלה, ואילו שמות קבצים OneDrive יסרב לסנכרן |
| `guide.py` | קובצי `README.txt` בעברית בתוך התיקייה המשותפת |

## פקודות

```bash
python -m moodle ingest <מזהה מטלה>
```
משיכה. בפעם הראשונה של מטלה חדשה מוסיפים `--course "Linear Algebra" --name "Assignment 1 - Vectors"`.

```bash
python -m moodle upload <מזהה מטלה>
```
הכנת ההחזרה לתיקייה `3 - Ready to upload to Moodle`.

```bash
python -m moodle send <מזהה מטלה> [--dry-run] [--yes] [--simulate]
```
העלאה אוטומטית למודל דרך Claude in Chrome. מכינה אצווה (רק עבודות חדשות או ששונו), מדפיסה סיכום במספרים בלבד, שואלת `להעלות למודל? (y/N)` (אלא אם יש `--yes`), ומעלה ZIP אחרי ZIP תוך רישום ב-`Upload log.csv`. `--dry-run` רק בודק את הדף ומצרף את הקובץ, ונעצר בביטול לפני הייבוא (הייבוא במודל מיידי, בלי מסך אישור): שום דבר לא מיובא ולא נרשם. `--simulate` לא נוגע במודל בכלל. קוד יציאה 1 אם נעצר לפני הסוף.

```bash
python -m moodle record <מזהה מטלה> "<שם ה-ZIP>"
```
למי שהעלה ZIP ביד לפי `Upload steps.txt`: רושם את הקבצים שלו ב-`Upload log.csv`, כדי שהאתר ידע מה הוחזר. ה-ZIP נמצא בתיקייה של האצווה הנוכחית (`Upload batch <id>/`), ואם הוא חסר או השתנה מאז ההכנה, לא נרשם כלום.

```bash
python -m moodle status <מזהה מטלה>
```
מראה מה כבר נעשה במטלה.

אותן פעולות זמינות גם בכפתורים של האתר המחובר (ראו [`dashboard/`](../dashboard/)).

## קבצי ההעלאה

בתיקייה `3 - Ready to upload to Moodle`:
- `Upload log.csv`: יומן ההעלאה, עם העמודות `number,file,sha256,zip,uploaded_at,by`. מספרים בלבד, בלי שמות. רק פייתון כותב אותו (לא Claude).
- `Upload batch.json`: רשימת האצווה האחרונה שהוכנה, עם התיקייה שלה וה-sha256 של כל ZIP.
- `Upload batch <id>/`: קובצי ה-ZIP של האצווה (`Graded - part 01.zip`...). ההכנה הידנית ("הכנת החזרה", `upload`) כותבת את ה-ZIP-ים שלה ישר לתיקיית ההעלאה ולא נוגעת בתיקייה הזו. הכנה חדשה מוחקת את התיקיות של אצוות קודמות, אבל רק את ה-ZIP-ים שהקוד כתב: עותקים כפולים של OneDrive לא נמחקים לעולם.
- `Upload steps.txt`: השלבים בעברית למי שמעלה ביד.

בתיקיית המטלה: `Upload in progress.txt`, נעילה שקיימת רק בזמן שמעלים. בזמן הזה גם "הכנת החזרה" באתר ו-`send` ב-CLI מסרבים.

## מה חשוב לדעת על מודל

- הייבוא מתבצע מיד בלחיצה על "יבוא קבצי משוב". אין מסך אישור (קובץ לסטודנט) לפני הייבוא. הבדיקה היחידה היא ההודעה של מודל אחרי הייבוא, "N קבצים יובאו", מול מספר הקבצים ב-ZIP. לכן בדיקה יבשה לא לוחצת על הכפתור.
- ה-ZIP שנבנה כאן (תיקייה `<שם>_<מזהה משתתף>_assignsubmission_file/feedback.pdf`) נבדק ויובא בהצלחה אל הסטודנט הנכון במטלה 3438636.
- Claude Code צריך להיות מחובר פעם אחת בכל מחשב שמעלה. האתר מציג רשימת מוכנות לפני ההעלאה, ומפעיל את ההתחברות בעצמו.

**מזהה המטלה** הוא המספר `id=` בכתובת של המטלה במודל. הוא גם המספר בסוף שם ה-ZIP.

ההסבר המלא נמצא ב-[`CLAUDE.md`](../CLAUDE.md): איך מורידים, איך מעלים, ובעיות שכבר נפתרו.

הבדיקות נמצאות ב-[`tests/moodle/`](../tests/moodle/).

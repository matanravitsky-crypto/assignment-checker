# משיכה והחזרה ידניות: האדם מול מודל, הקוד מול התיקייה, אתה מול שניהם

**העיקרון (אורי, 2026-11-16): Claude לא ניגש למודל.** לא פותח, לא מוריד, לא מעלה, לא בודק חיבור, לא משנה הגדרות. גם לא "רק לבדוק".
האדם עושה את זה בדפדפן שלו. אתה מריץ את הקוד, קורא את הדוחות, ואומר לאדם מה המצב ומה הצעד הבא. מספרים בלבד, אף פעם לא שם של סטודנט.
המדריך המלא לאנשים: `docs/Protocol - manual pull and return.md`.

## 0. איפה אני (פעם אחת בתחילת כל שיחה)

```bash
python -m moodle list
```
מדפיס את תיקיית הנתונים שהמחשב הזה רואה, ולכל מטלה: קורס, הגשה, מזהה מודל, כותרת, כמה נמשכו, נבדקו והוחזרו.
- "התיקייה המשותפת המסונכרנת": התיקייה של הצוות מ-OneDrive (`YallaLinearit`, דרך "Add shortcut to My files"). זה המצב הרצוי: כל הצוות רואה את אותם קבצים.
- "עותק מקומי": עובד, אבל מה שנכתב כאן מגיע לצוות רק אם מעלים אותו ל-OneDrive. להגיד את זה לאדם.
- "התיקייה לא קיימת": צריך את התיקייה המשותפת, או `ASSIGNMENT_DATA` ב-`.env` של הריפו שמצביע על עותק של `Exercise Checking System`. לא ממשיכים בלי זה.
הפקודות רצות מתיקיית הריפו עם ה-`.venv` שלו (`start.bat` מתקין). 7-Zip חייב להיות מותקן למשיכה.

## 1. על איזו מטלה מדובר (לפני כל פעולה)

האדם אומר קורס והגשה ("לינארית הגשה 2"). אתה מוצא את השורה ב-`list`, ומציג כרטיס לאישור, שורה אחת:
"אלגברה לינארית, הגשה 0 (קבוצות ומרוכבים), מזהה 3438636, נמשכו 1,078, בדוקות 80, הוחזרו 0. זו המטלה?"
- המזהה הוא המספר שבסוף כתובת המטלה במודל (`id=`) ובסוף שם ה-ZIP שמודל מוריד. האדם לא מקליד אותו; הקוד מצליב.
- הגשה בלי מזהה (עוד לא נמשכה): מבקשים פעם אחת את הקישור לעמוד המטלה במודל, לוקחים ממנו את המספר, ובמשיכה הראשונה נותנים `--course` ו-`--name` באנגלית.
- לא מריצים כלום לפני שהאדם אישר את הכרטיס. `<מזהה>` בהמשך = המספר מהכרטיס.

## 2. משיכה

**מה אומרים לאדם** (בדיוק זה, לא יותר):
1. פתח במודל את עמוד ההגשות של המטלה.
2. ודא שמסומן "הורדת הגשות המאורגנות לתיקיות לפי סטודנט" (ליד "פעולות").
3. עד כמאה הגשות: פעולות ← "הורדת כל ההגשות". יותר: "הצגה" 100 בעמוד, בכל עמוד "בחר הכול" ← "הורדת ההגשות שנבחרו", עמוד אחרי עמוד. לא לשנות שמות, לא לפתוח.
4. כמה "הוגש" כתוב בראש העמוד? תגיד לי את המספר.

**מה אתה מריץ** כשהאדם אומר "הורדתי, הוגש N":
```bash
python -m moodle ingest <מזהה> --expected N
```
לוקח כל ZIP של המטלה שמחכה ב-Downloads (גם העותקים `(1)`, `(2)`), מדפיס את הרשימה, בודק כל אחד, מחלץ, ממספר פעם אחת (סטודנט שהופיע בשני עמודים נספר פעם אחת, מי שכבר היה לו מספר שומר עליו), ומדפיס את `Pull report.txt`.
**מה אתה אומר לאדם:** את הדוח במילים שלך: כמה הגיעו, כמה היו צפויים, תואם או חסר. חסרים: "כנראה עמוד שלא ירד, הורד אותו ותגיד לי". משיכה נוספת מוסיפה רק מה שחדש.
הדוח נשאר בתיקיית המטלה (`Pull report.txt`, `Pull check.json`, `Pull log.csv`), ו-`python -m moodle list` מראה את המצב בכל עת.

## 3. החזרה (הדגש של הסקיל)

**תנאי פתיחה** (בודקים ב-`list` ואומרים לאדם): יש עבודות בדוקות, ולהן ציונים שמתרגל אישר. כל סקיל בדיקה חייב לכתוב ל-`2 - Graded with comments/<מספר>.pdf` ולקובץ `Grades by <שם>.csv`: ההחזרה מכירה רק אותם.

**מה אומרים לאדם לפני ההכנה:** "אם רוצים להחזיר גם ציונים: פעולות ← 'הורדת גיליון ציונים' (מופיע רק כש'גיליון ציונים לא מקוון' דלוק במטלה; המרצה מדליק). תוריד אותו עכשיו ותגיד לי." בלי הגיליון, העבודות מוכנות והציונים לא.

**מה אתה מריץ:**
```bash
python -m moodle upload <מזהה>              # ZIP-ים של עד 730 MB (מודל מקבל 750)
python -m moodle upload <מזהה> --max-mb 100  # בפעם הראשונה של הצוות, או אם הדף במודל אומר גבול אחר
```
הקוד: אורז רק עבודות חדשות או ששונו מאז ההעלאה האחרונה, ממלא את גיליון הציונים לפי מזהה המשתתף (אף פעם לא לפי סדר שורות), ואז **מאמת הכול מחדש מהדיסק**: פותח כל ZIP, ולכל קובץ בודק שהתיקייה היא זו שטבלת המפתח נותנת למספר, שהקובץ זהה בייט לבייט לעבודה הבדוקה של אותו מספר, שהציון בגיליון הוא ציון אותו מספר, שאף אחד לא פעמיים ואף אחד לא חסר. כישלון אחד: האצווה נמחקת, שום דבר לא "מוכן", והסיבה מודפסת. הצלחה: `Return check.txt` בתיקיית המטלה, ו-`Upload steps.txt` ב-`3 - Ready to upload to Moodle`.
הפקודה מסרבת (ואומרת למה) בזמן משיכה או העלאה של המטלה, כשיש עותק כפול של OneDrive, וכשטבלת המפתח לא עקבית. לא עוקפים.

**מה אתה אומר לאדם אחרי ההכנה:** כמה סטודנטים, כמה ZIP-ים, הגודל של כל אחד ומספר הקבצים בו, שהאימות עבר, והאם הציונים מולאו. ואז ההוראות, בדיוק אלה, עם הקישורים שהפקודה הדפיסה:
1. פתח את דף ההעלאה (הקישור, או לחיצה כפולה על "Open the upload page in Moodle" שליד ה-ZIP-ים). גרור לתוכו את `Graded - part 01.zip` ולחץ "יבוא קבצי משוב". הייבוא מיידי, בלי מסך אישור.
2. מודל מציג "N קבצים יובאו". תגיד לי את N.
3. (אחרי שכל ה-ZIP-ים עלו, ורק אם הגיליון מולא) פתח את דף העלאת הציונים (הקישור השני), גרור לתוכו את `Grades for Moodle worksheet.csv` ← מודל מציג רשימת שינויים ← אשר רק אם מספר הציונים הוא <המספר שההכנה הדפיסה>. אחר כך מחק מ-Downloads את הגיליון שהורד (יש בו שמות).

**מה אתה מריץ כשהאדם אומר "מודל אמר N":** משווה ל-N של אותו ZIP ב-`Upload steps.txt`.
- תואם: `python -m moodle record <מזהה> "Graded - part 01.zip"`, ואומרים "נרשם, הבא בתור: part 02".
- לא תואם: עוצרים. לא ממשיכים ל-ZIP הבא, לא מריצים `record`. "מודל ייבא N במקום M: תפתח את עמוד ההגשות ותבדוק מי חסר לפני שממשיכים." (העלאה חוזרת של אותו ZIP מחליפה, לא מכפילה.)
`record` מסרב ל-ZIP שחסר או שהשתנה מאז ההכנה: אז מכינים שוב.

## מה אסור, תמיד
- לפתוח מודל, להוריד או להעלות אליו, להריץ בו סקריפט, לבדוק בו חיבור, לשנות בו הגדרות. הפקודות הישנות של ההעלאה האוטומטית קיימות בקוד ולא מריצים אותן.
- לפתוח את טבלת המפתח, `Moodle originals` או את הגיליון שהורד. לכתוב שם, ת"ז או מייל בצ'אט, בקומיט או בלוג.
- למחוק או לבנות מחדש את טבלת המפתח. לחלץ ZIP ביד לתוך התיקייה. להעלות את ה-ZIP-ים ממודל או `Moodle originals` ל-OneDrive או ל-GitHub.
- להתאים ציונים לפי סדר שורות. תמיד לפי מספר ולפי מזהה משתתף.

# grading/: שלב הבדיקה עם Claude

בודק את העבודות לפי החוזה של שאר המערכת: קורא רק את ההגשות הממוספרות, וכותב את מה ש-`python -m moodle upload` מצפה לו.

באתר המחובר: בשלב "בדיקה וציון" לוחצים **"בדוק"**. משורת הפקודה:

```bash
python -m grading <מזהה מטלה>
python -m grading <מזהה מטלה> --ids 0001 0002
```

בלי `--ids` נבדק כל מה שעוד לא נבדק. עם `--ids` נבדקות רק ההגשות האלה, גם אם כבר נבדקו.

## מה הבדיקה מקבלת

בתיקיית כל מטלה, בתיקייה המשותפת:
- `1 - Submissions to grade/0001.pdf`…: ההגשות, ממוספרות ובלי שמות. רובן צילומים של כתב יד. אם סטודנט הגיש כמה קבצים (`0001.pdf`, `0001-2.jpg`…), הם נבדקים יחד כעבודה אחת. קבצים שהם לא PDF או תמונה (למשל docx) לא נבדקים, והעבודה מסומנת לבדיקה ידנית.
- `Assignment details.json`: השאלות (`questions`), הכללים (`submission_rules`), הציון המרבי (`max_grade`, ברירת מחדל 100), המחוון (`rubric`) והנחיות לבדיקה (`grading_instructions`).
- `Official solution.pdf` בתיקיית המטלה, אם יש: נשלח ל-Claude עם כל הגשה.

**הניקוד ניתן אך ורק לפי המחוון.** לכל שאלה הניקוד שלה במחוון, ולא יותר. המערכת לא מחלקת ניקוד בעצמה (אין חלוקה שווה),
ובלי מחוון אין ציונים: הבדיקה עם Claude והאישור בבדיקה הידנית מסרבים (`NoRubric`), והאתר מראה למה.
ניקוד ש-Claude נתן מעל המחוון נחתך, והעבודה עוברת לבדיקה ידנית. ניקוד מעל המחוון לא מאושר בבדיקה הידנית.

**המחוון** (`rubric`) הוא אובייקט, עם ניקוד לכל שאלה (חובה) ודגשים:
  ```json
  "rubric": {
    "questions": [
      {"label": "דף קבוצות 11", "points": 20, "criteria": "הכלה בשני הכיוונים",
       "deductions": [{"text": "חסר נימוק להכלה ההפוכה", "points": 5}]},
      {"label": "דף קבוצות 12", "points": 20}
    ],
    "notes": "לא מורידים נקודות על טעות חישוב קטנה"
  }
  ```

`deductions` (לא חובה): טעויות מוכרות לשאלה ובכמה מורידים עליהן. Claude משתמש בניסוח שלהן, והן ההערות המוכנות בבדיקה הידנית באתר.

## מה Claude עושה

כל הגשה נשלחת כתמונות של העמודים (`render.py`), עם השאלות, המחוון, הכללים, ההנחיות והפתרון. מה שמשותף לכל ההגשות נשמר במטמון (prompt caching), כדי שכל הגשה נוספת תעלה פחות. Claude מחזיר JSON בסכמה קבועה:
- ניקוד ומשפט קצר לכל שאלה, סוגי הטעויות בה (בניסוח כללי, כדי שאותה טעות תיספר יחד בכל העבודות), והאם הוא לא בטוח בניקוד שלה.
- משוב לסטודנט.
- סימונים: עמוד, מלבן (באלפיות של רוחב העמוד ושל גובהו) והערה קצרה.
- האם אדם צריך לבדוק את העבודה, למה בדיוק (איזו שאלה, איזה עמוד), ואיזה סוג בעיה: `unreadable`, `missing`, `uncertain`, `format`, `other`.

את הציון מחשבת המערכת מהניקוד של השאלות, לא Claude. ברירת המחדל היא `claude-opus-5-5`, ואם הוא מסרב לבדוק עבודה, הבקשה עוברת לבד למודל אחר. הגשה שנכשלה לא עוצרת את השאר.

## מה הבדיקה מחזירה

- `2 - Graded with comments/0001.pdf`: כל העבודה של הסטודנט, עם סוגר אדום ממוספר בשוליים הימניים, לאורך השורות של כל טעות (לא מלבן על מה שהסטודנט כתב). ההערות עצמן כתובות בפס לבן שמתחת לאותו עמוד (העמוד מוארך בשבילו). סימון גבוה מ-25% מהעמוד נחתך. בהתחלה נוסף עמוד עם הציון, ואחריו לכל שאלה שורה "20/20 - דף קבוצות, שאלה 11" והערה (שאלה בלי מה לתקן: "תשובה נכונה"). המשוב הכללי לא בעמוד הזה אלא רק בעמודה `feedback` של קובץ הציונים. קטע מתמטיקה בתוך עברית נכתב משמאל לימין (`ltr_runs`). **עד 2 MB לקובץ**: סריקה גדולה נדחסת, אחרת היא לא נכנסת למודל.
- `Grading notes/0001.json`: מה Claude אמר על כל שאלה (הערה, טעויות, לא בטוח), הסימונים, וסוג הבעיה. אם הבדיקה של עבודה נכשלה, הסיבה (`error`). רק מספרים, בלי שמות. מזה האתר בונה את הטעויות הנפוצות ואת תור הבדיקה הידנית.
- שורה בקובץ הציונים של הבודק, `Grades by <שם>.csv` (ראו "חלוקה בצוות" למטה), עם העמודות:

| עמודה | מה |
|---|---|
| `number`, `grade`, `feedback` | מה ש-`moodle upload` קורא |
| `points` | ניקוד לכל שאלה, לפי הסדר, מופרד ב-`;` |
| `approved` | ריק עד שמישהו מאשר. **שורה שיש בה משהו כאן לא נבדקת שוב ולא נדרסת** |
| `review` | למה Claude ביקש שאדם יבדוק (ריק אם לא ביקש) |
| `graded_at`, `graded_by` | מתי נבדקה ומי בדק |

עמודות שמישהו הוסיף ל-`Grades.csv` נשמרות.

## חלוקה בצוות

כמה אנשים יכולים לבדוק את אותה מטלה בבת אחת, כל אחד במחשב שלו ובמנוי Claude שלו:
- **מי לוקח מה** (`moodle/claims.py`): באתר, בשלב הבדיקה, כל אחד לוקח עבודות ("קח" ליד עבודה, או "קח N עבודות פנויות"). זה נשמר בקובץ משלו, `Who grades what/<שם>.json` בתיקיית המטלה, ו-OneDrive מעביר אותו לשאר הצוות. האתר בודק כל 5 שניות אם משהו השתנה בתיקייה, ומציג מי לקח מה. אם שניים לקחו אותה עבודה לפני ש-OneDrive סנכרן, מי שלקח ראשון שומר אותה.
- **"בדוק"** בודק רק את העבודות שלי. עבודה שמישהו אחר לקח לא נבדקת אצלי, וכל עבודה שנבדקת אצלי נרשמת עליי. כל עוד אף אחד לא לקח עבודות, "בדוק" בודק את כולן, כמו קודם.
- **הציונים** נכתבים לקובץ של הבודק, `Grades by <שם>.csv` (`moodle/grades.py`), ולא ל-`Grades.csv`: אם שני מחשבים היו כותבים לאותו קובץ, OneDrive היה שומר אחד מהם כעותק מתנגש וציונים היו נעלמים. מי שקורא ציונים (האתר, `moodle upload`, `moodle send`) מאחד את כל הקבצים: שורה מאושרת גוברת, אחריה הבדיקה האחרונה (`graded_at`). `Grades.csv` נשאר לציונים ישנים ולאישורים ביד.
- **השם** נשמר במחשב, ב-`.env` (`GRADER_NAME=...`), מהאתר. בלי שם, הבדיקה משתמשת בשם המשתמש של Windows.
## בדיקה ידנית

עבודה ש-Claude ביקש שאדם יבדוק, או שהבדיקה שלה נכשלה, מחכה בעמוד "בדיקה ידנית" באתר עד שמישהו מאשר אותה. שם רואים מה הבעיה, את השאלות ש-Claude לא בטוח בהן, ולכל שאלה הערות מוכנות (מהמחוון, מהטעויות הנפוצות ומה ש-Claude מצא) עם הניקוד שלהן: לחיצה על הערה מורידה את הנקודות וכותבת אותה. "אשר" קורא ל-`save_review`: מחשב את הציון, מעדכן את עמוד הציון בעבודה המסומנת, וכותב ב-`approved` מי אישר ומתי. שורה מאושרת לא נבדקת שוב.

## כללים

- שולחים ל-Claude רק את ההגשה הממוספרת. לעולם לא את טבלת המפתח, ולא שמות.
- Claude מתבקש לא לכתוב שמות. ליתר ביטחון, הקוד קורא את השמות מטבלת המפתח במחשב בלבד, ומוחק אותם מהמשוב ומההערות אם Claude העתיק אותם מהדף.
- מתאימים ציונים לפי מספר, אף פעם לא לפי סדר השורות.
- **דרך Claude Code או דרך ה-API.** עם `ANTHROPIC_API_KEY` ב-`.env` הבדיקה רצה דרך ה-API. בלי מפתח היא רצה דרך Claude Code שמחובר במחשב (`claude_cli.py`, במנוי של הצוות): לכל הגשה ריצה נעולה של `claude -p --tools Read` בתיקייה זמנית מחוץ ל-OneDrive, שיש בה רק תמונות העמודים (והפתרון), עם אותן הנחיות ואותה סכמה. בלי שניהם מופיעה הודעה שאומרת מה לעשות.
- Claude Code ישן לא מריץ את `claude-opus-5-5` ("version ... or newer is required"). `start.bat` מעדכן אותו בכל הפעלה, וידנית: `claude update`.
- במחשב של אורי PyMuPDF חסום (Windows Smart App Control). צריך לבדוק מה רץ במחשב שבודק.

| קובץ | מה הוא |
|---|---|
| `grade.py` | הבדיקה: הבקשה ל-Claude, התשובה, הסימון על ה-PDF וקובץ הציונים של הבודק |
| `claude_cli.py` | הבדיקה דרך Claude Code כשאין מפתח API |
| `render.py` | הופך כל עמוד בהגשה לתמונה, לשליחה ל-Claude |
| `submission.py` | מבנה של הגשה כפי שמגיעה ממודל |
| `__main__.py` | `python -m grading` |
